# GlobalPulseAI 营销站设计规范

> **适用范围**：`Home`、`Product`、`Cases`、`About`、`Pricing` 等所有面向访客的营销页面。  
> **技术约束**：React + Tailwind CSS；不引入额外 UI 组件库；组件使用相对路径导入（无 `@/` 别名）。  
> **全页对齐**：必须遵守 **§8 对齐系统**。**Hero / 正文 / CTA 纵向节奏**：必须遵守 **§9 视觉节奏**。

---

## 1. 设计目标（必须遵守）

### 1.1 整体视觉风格

- **信息结构**：参考主流 AI SaaS（OpenAI、Claude、Notion 等）——层次清晰、扫描成本低、主次分明。
- **排版气质**：结合 Apple 风格——克制留白、对齐严谨、少装饰多内容。

### 1.2 核心气质

| 关键词 | 含义 |
|--------|------|
| 简洁 | 每屏信息量少而准，避免堆砌 |
| 克制 | 颜色、动效、装饰元素点到为止 |
| 高级 | 通过留白与层级体现品质，不靠花哨特效 |
| 可信 | 用事实、结构、一致性建立信任 |
| 不炫技 | 避免为展示而展示的动画与视觉技巧 |

### 1.3 禁止项

- 整页「标题 + 卡片」重复堆砌，无叙事推进。
- 多个 section 使用完全相同的布局模板。
- 大段空话、口号式文案而无具体指向。
- 过度渐变、霓虹、科技风粒子/光晕等强特效。
- 后台管理系统式密集表格、侧栏、多面板布局套在营销页上。

---

## 2. 页面结构标准（所有营销页统一骨架）

每个营销页必须包含以下逻辑层次（具体区块顺序可按页面微调，但**不得缺失**核心层）。

### 2.1 Hero 区（必选）

| 元素 | 要求 |
|------|------|
| 主标题 | 清晰表达产品或页面核心价值 |
| 副标题 | 一句话说明「是什么 / 为谁 / 解决什么」 |
| 主 CTA | 如：开始使用、免费试用等 |
| 次 CTA | 如：查看定价、了解产品 |

**禁止**：仅标题 + 大面积空白、无行动引导。

### 2.2 内容叙事区（必选，2～4 个 section）

- 每个 section **只表达一个清晰主题**（一个想法说完再换下一屏）。
- **布局必须多样化**：禁止所有 section 使用同一种「标题 + 描述 + 三/四宫格卡片」。

**允许的结构示例**：

- 左文右图 / 右文左图（图文叙事）
- 单列长文 + 单张插图或示意
- Step / 流程（编号步骤、时间线）
- **少量**卡片（feature、要点），但**不能**整页只有卡片

### 2.3 证明区（可选）

- 案例摘要、使用场景、可量化或可归因的「结果」展示。
- 目的：让用户相信产品**有效**，而非仅「存在」。

### 2.4 结尾 CTA 区（必选）

- 明确下一步：注册、联系、查看定价等。
- **禁止**页面在正文结束后无收尾、无引导。

## 3. 组件与视觉规则

### 3.1 Typography（字体层级）

必须区分以下角色，**禁止所有标题使用同一字号**。

| 层级 | 用途 | Tailwind 建议 |
|------|------|----------------|
| Hero Title | 页面首屏主标题 | `text-4xl`～`text-5xl`，`font-bold`/`tracking-tight` |
| Section Title | 各 section 标题 | `text-2xl`～`text-3xl`，`font-semibold` |
| Eyebrow | 小标签、章节前缀 | `text-xs`～`text-sm`，`uppercase`/`tracking-wide`，`text-gray-500` |
| Body | 正文 | `text-base`～`text-lg`，`text-gray-600`～`text-gray-700` |
| Caption | 辅助说明、脚注 | `text-xs`～`text-sm`，`text-gray-500` |

### 3.2 Spacing（间距系统）

统一节奏，但**允许**在 Hero / 强调区与正文区之间略有变化，避免「所有区块间距一模一样」的死板感。页面级 **Hero / 正文 / CTA 三类区域的节奏差异** 以 **§9 视觉节奏** 为准；本节保留 Tailwind 级数值参考。

| 场景 | 建议 |
|------|------|
| Section 上下 | `py-16`～`py-24`（按信息密度调整） |
| 标题 → 副标题 | `mt-3`～`mt-4` |
| 副标题 / 区块标题 → 主内容 | `mt-6`～`mt-8` |
| 卡片内边距 | `p-5` 或 `p-6` |

**禁止**：全站统一用一个 `py-12` 打天下；无节奏变化；或正文区过密导致廉价感。

### 3.3 Card 使用规则（重要）

**何时使用卡片**：

- 独立信息单元：单条 feature、单个 case、单个价值点等。

**禁止**：

- 整页全部是卡片网格。
- 长段落叙事强行塞进卡片。
- 卡片内再嵌套多层卡片（信息层级混乱）。

**数量建议**：

- 单页卡片 **2～6 个**为宜；若需更多，应拆 section 或改用列表/图文，而非无限加卡。
- 卡片作为视觉层级**不超过两层**（页面 → 卡片；避免卡片内再嵌套大卡套小卡）。

### 3.4 颜色规则

| 用途 | 建议 |
|------|------|
| 页面背景 | `bg-white` / `bg-gray-50`，可交替区分 section |
| 主文本 | `text-gray-900` |
| 次要文本 | `text-gray-600` |
| 品牌强调 | 蓝紫渐变（**仅**用于小范围强调） |

**渐变 / 品牌色允许出现的位置**：

- 主按钮（Primary）
- 选中/激活状态
- 图标或小面积 accent

**禁止**：

- 整屏或大段渐变背景。
- 多种高饱和色混用。
- 装饰性霓虹、描边发光等「营销模板」感过强的效果。

### 3.5 按钮规则

| 类型 | 样式 | 用途 |
|------|------|------|
| 主按钮 | 渐变或品牌色（与现有 `Navbar`/定价 CTA 一致） | 主路径：注册、开始使用、去结账 |
| 次按钮 | `border` outline 或 `bg-transparent` ghost | 次要：查看定价、了解更多 |

- **高度统一**：`h-10` 或 `h-11`（全站营销页一致即可）。
- 同一 Hero 内主 CTA 仅一个视觉最重的按钮。

### 3.6 Navbar / Footer

- 与全站保持一致，不在本规范中重复定义；**营销页不得**为单页单独重做一套导航或页脚结构。

## 4. 页面叙事规则（重点）

页面不是组件的拼接，而是**一条有起承转合的叙事线**。

### 4.1 各页面必须回答的问题

| 页面 | 必须回答 |
|------|----------|
| **Home** | 你是什么产品？解决什么问题？为什么值得现在用？ |
| **Product** | 产品如何工作？核心能力是什么？与其它方式有何不同？ |
| **Cases** | 在什么场景下用？能产出什么结果？（可定性、可归因） |
| **About** | 我们是谁？为什么做这件事？我们的信念与边界是什么？ |
| **Pricing** | 各档差异是什么？如何选？下一步如何付费/联系？ |

### 4.2 禁止的叙事方式

- 只有「标题 + 一段描述 + 卡片网格」，没有逻辑递进。
- Section 之间无衔接，读者不知道为什么要往下滚。
- 复制粘贴同一套文案结构到多个页面，仅替换关键词。

---

## 5. 工程与落地约束

1. **技术栈**：仅 React + Tailwind；不引入 shadcn、Radix 等 UI 库。
2. **不改动**（除非产品另有决策）：核心业务 API、Workspace 分析流程、路由结构；本规范**不**要求为规范而改路由。
3. **导入路径**：组件与工具使用相对路径，不使用 `@/` 别名。
4. **与现有代码一致**：新页面与改版应逐步对齐本规范；旧代码可分批迁移，不必一次性重写。

- [ ] 单页是否**最多**只有一个 **MarketingCard Grid**（`MarketingCard` + 多列 `grid`）区块？
- [ ] 是否**未**用 `div` + `border` + `shadow`/`rounded` 等组合**伪装**第二组「卡片区」？
- [ ] 第二组及以后的并列信息是否已改用 **FeatureSplit / FeatureList / Steps / 纯文本 Section**？

## 7. 组件层规范（代码落地，必须遵守）

本节与 `frontend/src/components` 中的实现**一一对应**；新页面与改版须优先使用这些组件，避免重复造「裸 div + 随意间距」。

### 7.1 布局基元

| 组件 | 路径 | 约定 |
|------|------|------|
| **Container** | `components/layout/Container.tsx` | `max-w-7xl`、`mx-auto`、水平 `px-6 md:px-8`。营销页每个 section 的**内容区**必须置于 Container 内（Hero / FeatureSplit 等已内置）。 |
| **Section** | `components/layout/Section.tsx` | 语义化 `<section>`，默认 `py-20`；若 `className` 中含 `py-*` 则**不**再追加默认纵向间距，以便首屏或收尾区单独控制。禁止用无语义的裸 `div` 替代整页区块。 |

### 7.2 Hero 模板

| 组件 | 路径 | 约定 |
|------|------|------|
| **Hero** | `components/sections/Hero.tsx` | 居中标题 + 副标题 + 主 CTA + 可选次 CTA；按钮区 `gap-3`、统一由页面传入 `Link`/`button`（样式在页面内用约定 class 保持一致）。**所有营销页首屏应复用 Hero**，不得复制一套标题区结构。 |

### 7.3 非卡片型 Section 模板

| 组件 | 路径 | 用途 |
|------|------|------|
| **FeatureSplit** | `components/sections/FeatureSplit.tsx` | 左文右图或右文左图（`reverse`）；用于产品说明、品牌故事等。 |
| **FeatureList** | `components/sections/FeatureList.tsx` | 纵向「图标 + 标题 + 描述」列表，替代多列卡片网格展示要点。 |
| **Steps** | `components/sections/Steps.tsx` | 编号步骤（1/2/3），用于「如何使用」等线性流程。 |

**目的**：禁止全站仅依赖「标题 + Card 网格」一种结构；叙事区应轮换使用 Split / List / Steps 等。

### 7.4 卡片：`MarketingCard` 与页面级约束（工程化）

| 组件 | 路径 | 约定 |
|------|------|------|
| **MarketingCard** | `components/ui/MarketingCard.tsx` | 统一 `p-5`、圆角边框与 hover；网格内配合 `h-full` 与 flex 保证等高。**禁止在 MarketingCard 内再嵌套 MarketingCard**。**禁止**在 `MarketingCard` 内再套一层复杂信息面板（如另一套带边框阴影的内容区），避免层级与对齐失控。 |

#### MarketingCard Grid 的定义（判定标准）

以下**同时满足**时，即视为 **MarketingCard Grid**（本规范中「卡片区」计数对象）：

1. 使用 **`MarketingCard`** 作为独立信息单元的外壳；
2. 使用 **`grid` / `flex` 多列**（含 `md:grid-cols-*` 等响应式多列）并排展示**多个**该类单元。

#### 唯一性规则（必须）

- **同一营销页中，最多只允许存在一个 MarketingCard Grid section。** 即：全页最多**一处**「多列并排的 `MarketingCard` 区域」。
- **计费、结账等页面的 `PlanCard`**、证据 **`EvidenceCard`** 等**不计入**上述「MarketingCard Grid」名额，但**禁止**在任一页面用「换组件名、换 class、换 `grid`/`flex` 列数」等方式，实质再造**第二组**「多列并排、每格一独立信息单元」的**卡片区**（见下条「伪装禁止」）。

#### 伪装禁止（禁止钻空子）

以下行为**禁止**，视为违反「单页最多一个 MarketingCard Grid」的等价规避：

- 用 `div` + `border` + `rounded-*` + `shadow` + `p-*` 手写「卡片」外观，与 `MarketingCard` 并排成多列，承载第二组**独立信息单元**；
- 将 `MarketingCard` 改名为其它 wrapper，但结构仍为 **多列并排 + 独立卡片式信息单元**；
- 将本应一组的信息拆成**两个** MarketingCard Grid section（**两段**多列 `MarketingCard`）。

若需要展示**第二组及以后**的并列要点，**必须**改用以下之一：

- **FeatureSplit**（图文叙事）；
- **FeatureList**（纵向列表）；
- **Steps**（流程）；
- **纯文本 Section**（无卡片网格）。

### 7.5 参考实现

- **About**（`pages/About.tsx`）：Hero → Mission（单列文本）→ Story（FeatureSplit）→ Values（**唯一** Card Grid，3×`MarketingCard`）→ CTA + 纯文本联系信息。

### 7.6 自检清单（组件层）

- [ ] 营销区块是否使用 `Section` + `Container`（或已内置 Container 的 sections 组件）？
- [ ] 首屏是否使用 `Hero`？
- [ ] 除允许的**单个** MarketingCard Grid 外，是否用 List / Split / Steps 之一做过至少一种不同结构？
- [ ] `MarketingCard` 是否未嵌套使用？卡片内是否未再套复杂面板？
- [ ] 单页是否**未**出现**第二个** MarketingCard Grid，**且未**用手写边框阴影 `div` 伪装第二卡片区？
- [ ] **§8**：全页是否服从默认对齐模式 A（正文左对齐、仅 Hero 与最终 CTA 可居中）？
- [ ] **§9**：Hero / 正文 / CTA 三类区域的节奏是否有明显区分（见 §9.1）？

## 8. 对齐系统（Alignment System）

本节约束**页面级横向对齐**，避免「Hero 居中、正文有的居中有的左对齐、标题与内容对齐不一致」等混乱阅读流。与 `Container`、`Hero`、`Section` 组件配合使用。

### 8.1 页面级主对齐模式

- **每个营销页必须选择且仅允许一种「内容区主对齐模式」**（首屏 Hero 与页尾 CTA 的例外规则见下，**不**计入「多种模式混用」）。
- **当前项目默认且必须采用「模式 A」**，除非产品文档**明确声明**该页采用其它模式（未声明则一律按模式 A 验收）。

**模式 A（GlobalPulseAI 营销站默认，必须执行）**

| 区域 | 对齐 |
|------|------|
| 首屏 **Hero** | **居中**（`Hero` 组件内统一实现） |
| **除 Hero 与最终 CTA 外**的所有内容 section | **左对齐**（`text-left`；标题与正文一致） |
| 页面 **最终 CTA 收尾区** | **允许居中**（`text-center` 或等价视觉收口），作为全页行动聚焦 |

**适用范围声明**：`Home`、`Product`、`Cases`、`About`、`Pricing` 等所有营销页**均按模式 A 执行**；若未来某页单独例外，须在需求或本文件中**显式写明**页名与对齐模式。

### 8.2 强制禁止项

- **禁止**在同一页的正文内容区之间**混用多种对齐方式**（例如：某 section 居中、某 section 左对齐），**唯一允许**的居中块为：**Hero** 与**最终 CTA 区**。
- **禁止**同一 section 内 **section 标题居中**而**正文左对齐**（或相反）。
- **禁止**「卡片区」与**该 section 的标题**采用不同对齐逻辑（二者必须同为左对齐，最终 CTA section 除外）。
- **禁止**在 **Hero 之外**再出现**中途居中的正文 section**（含大段 `text-center` 正文）。
- **禁止**用 **`max-w-*` + `mx-auto` + `text-center`** 等方式**伪造**居中的正文块（与模式 A 冲突时，一律视为违规）。

### 8.3 Section 级对齐规则

- **除 Hero 与最终 CTA 外**，所有 section **默认 `text-left`**。
- **Section 标题**默认 `text-left`。
- **Section 正文**默认 `text-left`。
- **FeatureSplit**、**FeatureList**、**Steps** 的标题与正文列默认 **左对齐**（与模式 A 一致）。
- **含 MarketingCard Grid 的 section**：标题与下方 `grid` **同一 Container 内左对齐**，卡片栅格左缘与标题左缘对齐。

### 8.4 自检清单（对齐）

- [ ] 页面是否存在 **「居中 → 左 → 居中」** 等**正文区中途**对齐切换（除 Hero 与最终 CTA）？
- [ ] **Hero 以外**是否出现**居中的正文区**？
- [ ] **section 标题与正文**是否**统一左对齐**（最终 CTA 区除外）？
- [ ] **Card grid** 与该 section **标题**是否从**同一左边界**（同一 `Container` 左内缘）起始？

## 9. 视觉节奏（Visual Rhythm）

本节约束 **Hero、正文、CTA** 三类区域的**纵向留白与阅读节奏**，与 §3.2 数值参考配合使用；**不**引入设计 token 或 Figma 变量。

### 9.1 三类区域的节奏差异

| 区域 | 角色 | 节奏要求 |
|------|------|----------|
| **Hero** | 首屏价值与行动 | **允许**更大上下留白，视觉集中；**必须**居中排布（模式 A）。 |
| **正文内容区** | 叙事与信息承载 | **节奏稳定、阅读优先**；**必须**左对齐（模式 A）；section 之间 **禁止** 忽大忽小的无规律间距。 |
| **CTA 收尾区** | 收口与下一步 | **允许**再次聚焦；**允许**居中；与正文之间 **必须有**明显**分隔感**（背景色、边框或间距变化之一即可），**禁止**夸张全屏特效或过度装饰。 |

### 9.2 节奏规则（必须）

- **Hero 与正文之间** **允许**有明显**节奏切换**（留白略大于正文首 section 亦可视为合理）。
- **正文内部**各 section：**必须**维持**稳定**纵向节奏；**禁止**相邻 section 间距毫无理由地忽大忽小。
- **CTA 区**与正文末 section：**必须**有**分隔感**，**禁止**与正文「糊成一片」；**禁止**用全屏强渐变、霓虹等**过度**夸张手段制造分隔。
- **禁止**全页所有 section 使用**完全相同**的 `py-*` 导致呆板；**禁止**完全无规律、随机的间距（见 §8、§3.2 与 §3）。

### 9.3 推荐节奏写法（方向性，非全页死值）

| 区域 | 纵向 padding 方向 |
|------|-------------------|
| **Hero** | **相对更大**（例如大于或等于正文标准 section 的 `py`，首屏更「呼吸」） |
| **正文**各 section | **稳定**（同一页内正文 section 的 `py` 应一致或仅有**有理由**的阶梯，如首段正文略紧、中段略松） |
| **CTA 收尾** | **中等偏大**（略强于正文平均一节，或等于 Hero 与正文之间的过渡，以「收口」感为准，**禁止**压过 Hero 的首屏权重） |

具体 Tailwind 类名仍按 §3.2 与 `Section` 组件默认约定执行；**禁止**脱离 §8 对齐要求单独用「超大留白」制造居中正文区。
